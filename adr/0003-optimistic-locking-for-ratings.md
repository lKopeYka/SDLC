# Оптимистичная блокировка при пересчете средней оценки

## Контекст и постановка задачи
Согласно требованию REQ-REL-001, система должна корректно пересчитывать среднюю оценку фильма при одновременных запросах (до 100 одновременных оценок). Если два пользователя одновременно поставят оценку одному фильму, может возникнуть состояние гонки (race condition), и средняя оценка пересчитается некорректно.

## Драйверы решения
* **Целостность данных:** Средняя оценка должна всегда соответствовать сумме всех оценок.
* **Производительность:** Блокировки не должны замедлять работу системы (REQ-PERF-002).

## Рассмотренные варианты
* **Вариант 1: Пессимистичная блокировка (Pessimistic Locking).** Блокировка строки в БД (`SELECT FOR UPDATE`) на время транзакции.
* **Вариант 2: Оптимистичная блокировка (Optimistic Locking).** Использование поля `@Version` в JPA сущности.

## Итог решения
Выбранный вариант: **«Оптимистичная блокировка»**, потому что конфликты при выставлении оценок возникают редко, и блокировать строку на чтение при каждом запросе неэффективно.

### Последствия
* **Хорошо, потому что** пользователи не блокируют друг друга при чтении данных.
* **Плохо, потому что** при редком возникновении конфликта (одновременная запись) одному из пользователей придется повторить операцию (или система сделает это автоматически через retry).

### Подтверждение
Сценарий проверяется интеграционным тестом: 100 потоков одновременно отправляют `POST /api/v1/ratings`. Итоговое значение среднего балла должно точно совпадать с математическим ожиданием.
